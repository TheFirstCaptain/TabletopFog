# F-010A: Campaign Handout Library

## Objective

Add campaign-wide image handout storage and GM add-and-browse controls separate
from encounter maps.

## User Value

The GM can prepare non-map images for a campaign without forcing each image
into the encounter workflow.

## Non-Goals

- Do not show handouts to players in this slice.
- Do not add rotation.
- Do not rename or delete individual handouts in this slice; track that as
  [F-010E](./F-010E.md).
- Do not add PDFs, text handouts, notes, folders, tags, search, or slideshow
  mode.
- Do not add encounter-specific handouts.

## Acceptance Notes

- A campaign can store handout metadata separately from encounter map metadata.
- Handout image assets are copied into a campaign-local handout asset folder.
- Original filenames are preserved as default display names.
- Supported image types align with map image support: PNG, JPEG, GIF, and WebP
  up to 100 MB.
- Invalid, mismatched, oversized, partial-failure, missing-asset, unsafe-path,
  and symlink-escape cases leave existing campaign data and assets unchanged
  where practical.
- The Campaign screen uses an `Encounters`/`Handouts` content switch so only
  one campaign content collection is visible at a time.
- Browsing or adding handouts does not change the Player Display.
- Campaign deletion is blocked while handouts remain, matching the existing
  delete-content-first protection for encounter maps.
