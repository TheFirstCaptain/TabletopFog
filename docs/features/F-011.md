# F-011: Campaign Waiting Screen Image

## Objective

Allow the GM to set one campaign-level image that replaces the plain Player
Display waiting state while a campaign is open and nothing is currently shown
to players.

## User Value

Always-on table displays can show campaign atmosphere and context between
encounters or handouts instead of a generic blank waiting message.

## Non-Goals

- Do not add slideshow mode.
- Do not add multiple campaign waiting images.
- Do not add text notes, campaign notes, or session notes.
- Do not add video, audio, PDF, or non-image waiting-screen media.
- Do not make opening or editing an encounter change the Player Display.
- Do not let the Player Display choose, upload, replace, remove, or mutate the
  campaign image.
- Do not add tokens, initiative, dice, character sheets, rules automation,
  dynamic lighting, cloud hosting, login, or authentication.

## Acceptance Notes

- The GM can upload, replace, and remove one Campaign Image from the
  create/edit campaign flow.
- The Campaign Image uses the same supported image inputs and validation
  expectations as map and handout upload unless implementation review finds a
  documented reason to differ.
- When no campaign is open, the Player Display keeps the current plain
  `Waiting for GM.` state.
- When a campaign is open and no encounter or handout is shown to players, the
  Player Display shows `Waiting for GM - <Campaign Name>`.
- If that campaign has a Campaign Image, the Player Display uses it as a
  background with the waiting text over it.
- If that campaign has no Campaign Image, the Player Display still shows
  `Waiting for GM - <Campaign Name>` without a background image.
- Showing an encounter or handout replaces the campaign waiting screen.
- Clearing the shown encounter or handout returns to the campaign waiting
  screen for the open campaign.
- Uploading, replacing, or removing the Campaign Image updates the Player
  Display live when players are currently on the campaign waiting screen.
- Uploading, replacing, or removing the Campaign Image does not change the
  Player Display while an encounter or handout is currently shown to players.
- The Player Display remains read-only.

## Clarification Notes

- On 2026-08-01, the user proposed replacing the generic `Waiting for GM`
  Player Display state with a campaign-specific screen saver for always-on
  displays.
- The Campaign Image should be set only from the create/edit campaign flow.
- The GM must be able to remove the Campaign Image, not only replace it.
- If no Campaign Image is set while a campaign is open, the Player Display
  should show `Waiting for GM - <Campaign Name>`.
- If a Campaign Image is set, the Player Display should render it like a
  background with the waiting text over it.
- Campaign Image changes should update live when players are currently on that
  waiting screen.

## Affected Systems

- GM view: create/edit campaign flow for Campaign Image upload, replace, and
  remove controls.
- Player view: campaign-specific waiting screen with optional background image
  and overlaid waiting text.
- Local server: campaign image upload, removal, asset serving, shared-state
  projection, and live update behavior.
- Map/fog rendering: encounter and handout display should continue to replace
  the campaign waiting screen without changing map, fog, zoom, pan, fullscreen,
  or handout rotation behavior.
- Storage: campaign metadata and one copied Campaign Image asset.
- Documentation: feature tracker, roadmap, acceptance tests, README,
  development docs, and feature record.

## Validation Plan

input validation, removal, recovery, and projection behavior; Chromium
GM/Player Display workflow coverage for waiting-screen fallback, background
rendering, live update behavior, and replacement by encounters or handouts;
and full `npm run quality` before completion. Manual iPad or always-on display
validation should be recorded if practical.
