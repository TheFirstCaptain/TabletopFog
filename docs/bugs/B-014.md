# B-014: Encounter Gallery Scroll Jumps On Shown Target Changes

## Summary

Changing the shown encounter in the Campaign Encounter gallery can move the
page viewport, making the screen appear to jump.

## Status

Resolved.

## Observed Behavior

When the GM changes which Encounter card is `Shown to Players`, the campaign
screen can shift vertically instead of preserving the current viewport.

## Expected Behavior

Changing the shown encounter should update card state in place without moving
the GM's scroll position.

## Reproduction

1. Open a campaign with at least two encounters.
2. Scroll the Campaign Encounter gallery so the cards are partially down the
   page.
3. Click `Show to Players` on a different Encounter card.
4. Observe the viewport moving vertically.

## Affected Systems

- GM view: Campaign Encounter gallery scroll position during re-render.
- Player view: unchanged.
- Local server: unchanged.
- Map/fog rendering: unchanged.
- Storage: unchanged.
- Network/device setup: unchanged.
- Documentation: bug tracker and F-010G evidence.

## Investigation Notes

- The issue was reported by the user with screenshots on 2026-07-31 during
  F-010G validation.
- Changing the shown target re-renders the Campaign screen, replacing the
  Encounter card DOM. Preserving the current scroll position around
  campaign-screen re-renders prevents the viewport from jumping while still
  allowing normal navigation to and from the Encounter Workspace.

## Validation Plan

Browser regression coverage scrolls the Encounter gallery, switches the shown
target to another encounter and back, and asserts `window.scrollY` remains
stable. Run focused Chromium coverage and full `npm run quality`.
